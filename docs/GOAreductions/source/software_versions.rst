Software Versions
=================

In using reduced data from GOA rhere are some subtleties regarding software
versions that are noted here.


DRAGONS version
---------------

Generally, GOA reduces data using the latest version of DRAGONS. We generally
update the GOA servers fairly promptly (within a few days or weeks at most)
when a new public DRAGONS release becomes available. The version of DRAGONS
that was used to generate a given data file is available in the header of the
reduced data file and by clicking the [R] link in the archive search form
results table to see the [R]eduction information.

If a new DRAGONS release makes significant changes that we expect will
improve the quality of reduced data for a mode previously supported by DRAGONS,
we will generally re-reduce all data taken in that mode with the new DRAGONS
release. This generally involved creating a new "processing tag" for the new
reduced data, so that the data reduced with the previous version remain
available. For modes where the new release does not substantially change the
processing, we will generally not reprocess previously processed data, we will
will keep the existing processing tag but process data using the new DRAGONS
version.

Occasionally, we have features or updates to add to DRAGONS that are needed by
GOA but are not worthy of a full public release of DRAGONS. In that case, we
essentially do an internal release - a new DRAGONS version number is assigned
and the released is tagged in the DRAGONS github repository, but it is not
packaged for public release. This should generally be inconsequential for end
users - you may occasionally notice files that have been reduced by a DRAGONS
version that was not publicly released; you can assume that this version is very
similar to the most recent preceding public release.


Conda environments
------------------

While the version of DRAGONS used is important, so is the version of all the
software dependencies used with DRAGONS. This can be a subtle and surprising
"gotcha". Updating the packages in your conda environment can break
compatability with existing data files, and also cause your installation to
generate data files that are not compatible with the same DRAGONS version
running on an older conda environment.

The ``asdf`` set of packages are a prime example of this. Upgrading ``asdf`` can
cause DRAGONS to create calibration files (notably processed Arcs) which are
not compatible with installations of the same DRAGONS version that have not
upgraded to a new version of ``asdf``.

On the GOA servers that carry out DRAGONS data reduction, we install a clean
and up-to-date conda environment at the same time as we deploy a new major or
minor release of DRAGONS. DRAGONS version number terminology is that the 3
version numbers (eg 4.2.1) are the major, minor and patch release numbers. We do
not deploy a new conda environment when installing a patch release.
This means that the DRAGONS dependencies installed by conda are
the latest compatible versions of those packages at the time that minor version
of DRAGONS was released. We then do not update packages in the conda environment
during the time we are using that DRAGONS minor version (eg 4.2).
We recommend this practice to our users, especially if you plan on sharing
reduced data with others.


Use of calibrations from GOA with DRAGONS
-----------------------------------------

DRAGONS has the ability to automatically fetch processed calibrations from GOA
for use in local data reduction. We strongly recommend using the most recent
public release of DRAGONS when using this feature. Calibrations are often (but
not always) "backwards compatible" in that (for example) a calibration generated
by DRAGONS version 4.1 will be useable with DRAGONS 4.2, but the reverse is not
necessarily true - a calibration generated by (for example) DRAGONS 4.2 may
contain metadata or other data structures that DRAGONS 4.1 does not know how to
handle. We also strongly recommend creating an up to date conda environment when
installing DRAGONS, and then not updating it until the next DRAGONS release
(see section on Conda Environments above)
